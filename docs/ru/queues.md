# Очереди и топология

Дескриптор `RabbitQueue` называет очередь, которую читает обработчик, и описывает, какой эта
очередь должна быть: долговечность, тип очереди, привязки к обменникам, предвыборка и сырые
аргументы `x-*`. Дескриптор пишут прямо в атрибуте `#[subscriber(..)]`:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:descriptor"
```

Форма с голой строкой `#[subscriber("orders")]` - это сокращение для `RabbitQueue::new("orders")`:
долговечная неэксклюзивная очередь без автоудаления, которую читают как есть.

## Объявление включают явно {#declaration-is-an-opt-in}

Дескриптор описывает топологию, которую ожидает подписка. По умолчанию на брокере ничего не
создаётся, а отсутствующая очередь - это ошибка подписки: инфраструктурой управляете вы. Сервис,
которому принадлежат его очереди, включает объявление для своего брокера:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:app"
```

С включённым объявлением подписка объявляет привязанные обменники (кроме встроенных `amq.*` и
обменника по умолчанию), очередь и привязки - в этом порядке. Объявление идемпотентно, пока
дескриптор совпадает с тем, что уже есть; повторное объявление с другими свойствами брокер отвергает
(`PRECONDITION_FAILED`).

## Типы очередей {#queue-types}

RabbitMQ выбирает реализацию очереди при объявлении, через `x-queue-type`, и тип уже существующей
очереди изменить нельзя. Дескриптор открывает его типизированной настройкой:

- `.queue_type(QueueType::Classic)` - классическая одноузловая реализация.
- `.queue_type(QueueType::Quorum)` - реплицируемая через Raft; обязана оставаться долговечной.
  Крейт отказывается объявлять недолговечную кворумную очередь, а не оставляет это на брокера.

Настройка `.default_queue_type(..)` на брокере действует на дескрипторы, которые тип не выбирают;
если тип не указан нигде, `x-queue-type` не отправляется и действует умолчание сервера.

RabbitMQ 4 по умолчанию запрещает временные (недолговечные) неэксклюзивные очереди: оставляйте
долговечность по умолчанию, если только очередь не объявлена с `.exclusive(true)`.

## Предвыборка {#prefetch}

`.prefetch(n)` на брокере задаёт окно `basic.qos` для каждой подписки: не более `n` неподтверждённых
доставок в работе. Так обратное давление доходит до брокера, потому что медленный потребитель
замедляет отправку, а не набирает буфер без ограничений. Дескриптор переопределяет окно для своей
очереди тем же вызовом `.prefetch(n)`. Без обоих сервер не ставит ограничения.

Счётчик - это `NonZeroU16`. AMQP читает `basic.qos(0)` как «без ограничения», а не как нулевой
предел, поэтому неограниченную предвыборку заказывают, не задавая её вовсе. Литерал пишите
макросом `nonzero!` фреймворка, который отвергает ноль на этапе компиляции, - так и сделано в
дескрипторе выше.

## Пакеты {#batches}

Обработчик, принимающий срез, читает целый пакет, а точка монтирования называет, насколько большим
пакет может быть:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:batches"
```

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:batches_mount"
```

В AMQP нет пакета на уровне протокола - брокер присылает по одному `basic.deliver`, - поэтому пакет
собирается на клиенте: доставки копятся, пока пакет не наберёт размер, заказанный в точке
монтирования, или пока с первой из них не пройдёт `.batch_wait(..)`, что наступит раньше. Точка
монтирования об этом не говорит ничего: регистрация пакета называет только размер, а как пакет
собирается - принадлежит дескриптору.

`.batch_wait(..)` по умолчанию равен 50 мс. Поднимайте его на медленном канале или на редкой
очереди, где полные пакеты стоят ожидания, и снижайте там, где поздний пакет дороже неполного.

Пакет может оказаться короче размера, потому что неполный пакет уходит в обработчик, а не ждёт
трафика, которого может и не быть. И в пакет попадает только то, что брокер уже прислал, поэтому
окно [предвыборки](#prefetch) уже размера пакета ограничивает каждый пакет этим окном: `.batch(n)`
сочетайте с предвыборкой не меньше `n`.

## Метаданные доставки {#delivery-metadata}

`AmqpContext` даёт метаданные доставки AMQP, которые не относятся ни к полезной нагрузке, ни к
заголовкам: обменник, ключ маршрутизации, признак повторной доставки и локальный для канала тег
доставки. У каждого поля есть ключ нулевого размера в `context::keys`, и обработчик называет нужные
ему поля параметрами-экстракторами, по одному ключу на поле:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_keyed_lanes.rs:metadata"
```

Обработчик, объявивший `ctx: &mut Context<'_, AmqpContext>`, читает те же поля через
`ctx.context(KEY)`. Прелюдия экспортирует ключи, но не тип контекста, поэтому его импортируйте из
`ruststream_lapin::context`.

## Воркеры с партиционированием по ключу {#keyed-worker-lanes}

Подписка может раскладывать обработку по нескольким воркерам через `workers(n, by_key)`, оставляя
доставки с одним ключом в одной партиции (порядок внутри ключа, параллельность между ключами):

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_keyed_lanes.rs:consumer"
```

Производитель кладёт ключ в `PARTITION_KEY_HEADER` (`amqp-partition-key`), а крейт читает его
обратно через трейт-совместимость `Partitioned`. Сам AMQP этот заголовок не интерпретирует, так что
это клиентское соглашение, не связанное с серверной маршрутизацией по хешу ниже.

## Недоставленные сообщения {#dead-letter}

`.dead_letter_exchange("dlx")` (и при необходимости `.dead_letter_routing_key(..)`) задаёт
собственный обменник очереди для недоставленных сообщений. Обработчик, отбросивший сообщение,
завершает его через `basic.reject(requeue = false)`, и сообщение уходит туда.

## Отложенный повтор {#delayed-retry}

Обработчик, вернувший `HandlerOutcome::retry_after(delay)`, просит повторную доставку не раньше
чем через `delay` - случай «ещё не готово», когда немедленный возврат в очередь крутил бы сообщение
вхолостую. По умолчанию рантайм закрывает это своим независимым от брокера запасным путём, и
отложенная копия ждёт в процессе сервиса, at-most-once на время окна; публикуется она под
собственным именем очереди, потому что именно оно адресует её на обменнике по умолчанию.
`.delay(..)` делает отложенный повтор нативным: сообщение паркуется в очереди ожидания на брокере
с собственным TTL и по истечении TTL уходит как недоставленное обратно в исходную очередь, так что
отложенная копия хранится на брокере, а перезапуск посреди окна ничего не теряет.

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:delay"
```

Очередь ожидания (по умолчанию `<queue>.retry`, иначе `Delay::dlx_ttl_named(..)`) - это
инфраструктура: она объявляется только под `declare_topology(true)`, в остальных случаях
разворачивайте её сами. Классическая очередь выпускает просроченные сообщения только с головы,
поэтому при сильно разных задержках берите по очереди ожидания на класс задержки (или кворумную
очередь).

Для нагрузок с сильно перемешанными задержками фича `plugin-dme` предлагает `Delay::plugin_dme()`,
которая вместо этого пропускает повторные доставки через плагин
[delayed-message-exchange](https://github.com/rabbitmq/rabbitmq-delayed-message-exchange): сообщение
уходит с заголовком `x-delay`, и плагин держит каждое независимо, так что короткая задержка никогда
не ждёт за длинной. Плагин должен быть включён на брокере - отсюда и фича.

## Обменник с согласованным хешированием (плагин) {#consistent-hash-exchange-plugin}

Чтобы разложить нагрузку на стороне сервера - разнести один поток по нескольким очередям, хешируя
ключ маршрутизации, - фича `plugin-consistent-hash` открывает `RabbitExchange::consistent_hash(..)`,
которая опускается до типа обменника из плагина
[`rabbitmq_consistent_hash_exchange`](https://github.com/rabbitmq/rabbitmq-server/tree/main/deps/rabbitmq_consistent_hash_exchange).
Каждая очередь привязывается со своим целым весом в качестве ключа маршрутизации, и брокер делит
пространство хешей пропорционально:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_consistent_hash.rs:shards"
```

Маршрутизация по согласованному хешу работает на брокере и делит поток между очередями, тогда как
воркеры с партиционированием по ключу делят работу одного потребителя между партициями. Включите
плагин на брокере, прежде чем им пользоваться; фича выключена по умолчанию, потому что плагин не
входит в стандартный RabbitMQ.

## Сырые аргументы {#raw-arguments}

Всё, чего дескриптор не описывает, отправляется дословно:

```rust
--8<-- "crates/ruststream-lapin/examples/lapin_topology.rs:arguments"
```

`AMQPValue` и `FieldTable` реэкспортированы из крейта ровно для этого.
