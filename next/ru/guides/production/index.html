    Промышленная эксплуатация

    Это руководство настраивает соединение сервиса на RabbitMQ для промышленной эксплуатации и описывает, что сервис делает, когда пропадает соединение или останавливается он сам.

    Соединение​

    • Вручную
    src/main.rs
    /// The broker as production runs it.
    fn broker(uri: String) -> LapinBroker {
        LapinBroker::new(uri)
            // What the management UI lists for this service's connection.
            .connection_name(concat!("orders ", env!("CARGO_PKG_VERSION")))
            // At most 64 unacknowledged deliveries per subscription.
            .prefetch(nonzero!(64))
    }

    fn service(broker: LapinBroker) -> RustStream {
        RustStream::new(AppInfo::new("orders", "0.1.0")).with_broker(broker, |b| {
            b.include(take_order);
        })
    }

    #[ruststream::app]
    fn app() -> impl App {
        // amqps://orders:secret@rabbit.internal:5671/shop in production.
        let uri = env::var("AMQP_URL").unwrap_or_else(|_| "amqp://localhost:5672".to_owned());
        service(broker(uri))
    }

        RustStream::new(AppInfo::new("orders", "0.1.0")).with_broker(broker, |b| {

        })

    fn app() -> RustStream {
        // amqps://orders:secret@rabbit.internal:5671/shop in production.
        let uri = env::var("AMQP_URL").unwrap_or_else(|_| "amqp://localhost:5672".to_owned());
        service(broker(uri))
    }

    fn main() -> ExitCode {
        run_main(app)
    }

    URI соединения задаёт всё соединение: схему, учётные данные, хост, порт и виртуальный хост. amqp://orders:secret@rabbit.internal:5672/shop входит под пользователем orders в виртуальный хост shop. Виртуальный хост по умолчанию / записывается как %2f. Параметры запроса, например heartbeat, перечислены в спецификации URI RabbitMQ. Сервис читает URI из переменной AMQP_URL, поэтому пароль не попадает в код.

    connection_name подписывает соединение в веб-интерфейсе управления, и оператор видит, какому сервису и какой его версии оно принадлежит. prefetch ограничивает число неподтверждённых доставок каждой подписки. Так медленный сервис сдерживает сервер (Очереди задач).

    LapinBroker::new только запоминает URI. Сервис подключается при запуске. Если URI не разбирается или сервер недоступен, запуск прерывается с ошибкой AmqpError::Connect.

    TLS​

    URI со схемой amqps:// подключается по TLS, обычно на порт 5671. TLS включает одна из трёх фич ruststream-lapin, и каждая включает соответствующую фичу lapin:

    ФичаБиблиотека TLS
    tls-native-tlsбиблиотека платформы: OpenSSL в Linux, Secure Transport в macOS, SChannel в Windows
    tls-rustlsrustls
    tls-rustls-ringrustls с криптопровайдером ring

    Сертификат сервера проверяется по доверенным корневым сертификатам выбранной библиотеки. Настройку сервера описывает руководство по TLS RabbitMQ. Строки зависимостей показывает компонент TLS.

    Документ AsyncAPI сервиса сообщает хост и версию AMQP, но не учётные данные и не виртуальный хост из URI, потому что документ публикуется и передаётся другим.

    Топология в промышленной эксплуатации​

    Промышленный сервис обычно работает с выключенным declare_topology, на очередях, которые создаёт и меняет эксплуатация. Тогда отсутствующая очередь прерывает запуск, и сообщения не теряются (Топология). Предел попыток кворумной очереди и очередь ожидания отложенной переобработки в такой схеме тоже настраиваются на сервере (Подтверждения, переобработка и недоставленные сообщения).

    Соединения и каналы​

    Весь сервис работает через одно соединение. Каждая подписка открывает собственный канал, поэтому ошибка на одной очереди не останавливает остальные. Публикации без подтверждения делят один канал. Издатель с подтверждениями, издатель с транзакциями канала и запрашивающая сторона открывают каждый собственный канал при первом использовании, потому что подтверждения, транзакции и direct reply-to - это состояние канала.

    При ошибке уровня канала RabbitMQ закрывает канал, например после публикации в несуществующий обменник. Соединение остаётся открытым, а издатель открывает новый канал при следующем вызове.

    Потеря соединения​

    Восстановление соединения по умолчанию выключено. LapinBroker::auto_recover(true) включает переподключение силами Lapin с экспоненциальной задержкой, в том числе при первом подключении. По умолчанию разрешено 16 повторных попыток; .recovery_retries(n) меняет предел, а ноль отключает повторные попытки. Lapin восстанавливает каналы, объявленные обменники, очереди, привязки, предвыборку, подтверждения издателя и потребителей через существующие объекты. Приложение не перезапускается, хуки запуска повторно не выполняются.

    Настройте heartbeat в URI, например amqp://localhost:5672?heartbeat=30, чтобы обнаруживать незаметный разрыв соединения. ConnectedLapinBroker::is_connected() проверяет AMQP-соединение для проверки готовности: при разрыве и после завершения работы результат равен false. Результат true не означает, что восстановление каналов и топологии завершилось или что обработчики исправны; эта проверка отделена от состояния сервиса в рантайме.

    Неудавшиеся публикации не отправляются повторно, а сроки ожидания ответов на уже отправленные RPC-запросы продолжают идти. ServerTxPublish требует auto_recover(false), поскольку состояние транзакции теряется при переподключении. Исчерпание попыток при запуске приводит к ошибке подключения; после запуска поток потребителя выдаёт завершающую ошибку чтения и заканчивается.

    Неподтверждённые сообщения в очередях, переживших разрыв, возвращаются RabbitMQ и могут прийти повторно с признаком Redelivered. Повторная доставка требует, чтобы обработчики допускали дубликаты. Отмена потребителя сервером на работающем канале, например после удаления очереди, завершает подписку.

    Остановка​

    SIGTERM или Ctrl+C останавливает сервис. Рантайм останавливает подписки и закрывает соединение штатно, по протоколу. RabbitMQ возвращает в очередь каждую доставку, которую сервис взял и не подтвердил, и её забирает другой экземпляр. Издатель или запрашивающая сторона, пережившие соединение, например в фоновой задаче, возвращают AmqpError::Closed и ничего не отправляют в закрытое соединение.

    Если завершение работы началось во время переподключения, ожидающие потребители пробуждаются, а завершение работы брокера не ждёт возвращения RabbitMQ. Существующие объекты сразу считаются закрытыми; восстановленное позже соединение закрывается в фоне, либо очистка заканчивается при исчерпании попыток.

    Тестирование​

    Тесты в файле примера запускают сервис с URI amqps:// с учётными данными и с URI, записанным с ошибкой. Внутри процесса URI разбирается так же, как его разбирает соединение, поэтому с URI, по которому сервис не смог бы подключиться, не запускается и тест. TLS и потеря соединения требуют сервера, поэтому их проверяет тест на сервере.
