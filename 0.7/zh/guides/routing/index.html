    交换机与路由

    本指南通过 RabbitMQ 交换机路由消息：按路由键、发给每个绑定的队列，以及按消息头。

    发布者从不直接写入队列。 它带着路由键发布到交换机，交换机把消息复制到每个绑定相匹配的队列。 在 RustStream 中，队列的绑定写在它的描述符上，消息发往哪个交换机则由发布策略决定。 路由键就是消息的名字：消息类型上的 #[outgoing(name = "..")]，或者发布时给出的名字。

    示例是一家网店：它在 topic 交换机上发布订单，在 fanout 交换机上发布价格变动，在 headers 交换机上发布发货信息。 Broker 声明交换机、队列和绑定，所以示例可以在空的 RabbitMQ 上运行（拓扑）。

    默认交换机​

    前面的每个服务都发布到默认交换机。 它是一个 direct 交换机，每个队列都以自己的名字绑定到它。 因此路由键为 orders 的消息到达 orders 队列，服务用 #[subscriber("orders")] 读取它，完全不需要绑定。 服务器和进程内 RabbitMQ 都拒绝在默认交换机上建立绑定。

    你自己的 direct 交换机以同样的方式路由：一个绑定指定一个路由键，消息只到达以其路由键原样绑定的队列。

    src/main.rs
    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    struct Order {
        id: u64,
        region: String,
    }

    /// An order event; its routing key is `order.placed.<region>`.
    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    struct OrderPlaced {
        id: u64,
        region: String,
    }

    /// Takes an order from the `orders` queue and announces it on the `events` exchange.
    #[subscriber("orders")]
    async fn place_order(order: &Order, Out(events): Out<impl Publisher>) -> HandlerOutcome {
        let placed = OrderPlaced {
            id: order.id,
            region: order.region.clone(),
        };
        let key = format!("order.placed.{}", order.region);
        if events.message(&placed).to(&key).publish().await.is_err() {
            return HandlerOutcome::retry();
        }
        HandlerOutcome::ack()
    }

    /// Every order event of every region.
    #[subscriber(RabbitQueue::new("notifications.orders")
        .bind(RabbitExchange::topic("events"), "order.placed.*"))]
    async fn notify_customer(event: &OrderPlaced, Ctx(key): Ctx<RoutingKey>) -> HandlerOutcome {
        tracing::info!(event.id, routing_key = %key, "customer notified");
        HandlerOutcome::ack()
    }

    /// The events of the EU region only.
    #[subscriber(RabbitQueue::new("warehouse.eu")
        .bind(RabbitExchange::topic("events"), "*.*.eu"))]
    async fn reserve_stock(event: &OrderPlaced) -> HandlerOutcome {
        tracing::info!(event.id, "stock reserved in the EU warehouse");
        HandlerOutcome::ack()
    }

    /// Every event on the exchange, whatever its key.
    #[subscriber(RabbitQueue::new("audit").bind(RabbitExchange::topic("events"), "#"))]
    async fn audit(event: &OrderPlaced, Ctx(key): Ctx<RoutingKey>) -> HandlerOutcome {
        tracing::info!(event.id, routing_key = %key, "event audited");
        HandlerOutcome::ack()
    }

    /// Takes an order from the `orders` queue and announces it on the `events` exchange.
    struct PlaceOrder;

    impl<Events> Handle<Order, (), Outs<(Events,)>> for PlaceOrder
    where
        Events: OutEntry<DefaultSlot, Wire: Publisher>,
    {
        async fn handle(
            &self,
            order: &Order,
            outs: &Outs<(Events,)>,
            _ctx: &mut Context<'_>,
        ) -> Result<(), HandlerOutcome> {
            let placed = OrderPlaced {
                id: order.id,
                region: order.region.clone(),
            };
            let key = format!("order.placed.{}", order.region);
            let sent = outs
                .get(DefaultSlot)
                .message(&placed)
                .to(&key)
                .publish()
                .await;
            sent.map_err(|_| HandlerOutcome::retry())
        }
    }

    /// Every order event of every region.
    struct NotifyCustomer;

    impl Handle<OrderPlaced, (), (), AmqpContext> for NotifyCustomer {
        fn handle(
            &self,
            event: &OrderPlaced,
            _outs: &(),
            ctx: &mut Context<'_, AmqpContext>,
        ) -> impl Future<Output = Result<(), HandlerOutcome>> {
            tracing::info!(event.id, routing_key = %ctx.context(RoutingKey), "customer notified");
            ready(Ok(()))
        }
    }

    place_order 把每个订单作为 OrderPlaced 发布，路由键为 order.placed.<region>。 该类型没有声明名字，所以发布时用 .to(&key) 指定。 topic 交换机把路由键与每个绑定的模式逐词比较，词与词之间以点分隔。 * 恰好匹配一个词，# 匹配任意多个词，包括零个。

    因此 order.placed.* 接收所有地区的订单，*.*.eu 只接收欧盟的订单，# 接收这个交换机上的所有消息。 来自美国的订单到达通知和审计，欧盟仓库永远看不到它。 处理器通过 Ctx<RoutingKey> 读取消息到达时所带的路由键。

    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    struct PriceChange {
        sku: String,
        price_cents: u64,
    }

    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    #[outgoing(name = "price.changed")]
    struct PriceChanged {
        sku: String,
        price_cents: u64,
    }

    /// Applies a price change from the catalog and announces it to every reader of `prices`.
    #[subscriber("catalog.prices", reply)]
    async fn change_price(change: &PriceChange) -> PriceChanged {
        tracing::info!(change.sku, change.price_cents, "price changed");
        PriceChanged {
            sku: change.sku.clone(),
            price_cents: change.price_cents,
        }
    }

    #[subscriber(RabbitQueue::new("storefront.prices").bind(RabbitExchange::fanout("prices"), ""))]
    async fn refresh_storefront(change: &PriceChanged) -> HandlerOutcome {
        tracing::info!(change.sku, "storefront price refreshed");
        HandlerOutcome::ack()
    }

    #[subscriber(RabbitQueue::new("search.prices").bind(RabbitExchange::fanout("prices"), ""))]
    async fn reindex(change: &PriceChanged) -> HandlerOutcome {
        tracing::info!(change.sku, "search index updated");
        HandlerOutcome::ack()
    }

    fanout 交换机把每条消息复制到绑定它的每个队列，并忽略路由键。 change_price 以 PriceChanged 作为回复，店面和搜索索引各得到一份副本。 绑定的路由键为空，因为这个交换机不读取路由键。 新增一个价格变动的读者，只是多一个绑定到 prices 的队列；发布者不需要改动。

    headers 交换机​

    • 手写
    src/main.rs
    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    struct PaidOrder {
        id: u64,
        region: String,
        tier: String,
    }

    #[derive(Debug, PartialEq, Serialize, Deserialize, Outgoing)]
    #[outgoing(name = "shipment")]
    struct Shipment {
        order_id: u64,
        region: String,
        tier: String,
    }

    /// Ships a paid order, with its region and tier as headers, which the exchange routes on.
    #[subscriber("orders.paid")]
    async fn ship_order(order: &PaidOrder, Out(shipments): Out<impl Publisher>) -> HandlerOutcome {
        let shipment = Shipment {
            order_id: order.id,
            region: order.region.clone(),
            tier: order.tier.clone(),
        };
        let mut attributes = HeaderMap::new();
        attributes.insert("region", order.region.clone());
        attributes.insert("tier", order.tier.clone());
        let sent = shipments
            .message(&shipment)
            .with_headers(attributes)
            .publish()
            .await;
        if sent.is_err() {
            return HandlerOutcome::retry();
        }
        HandlerOutcome::ack()
    }

    /// The binding arguments: how to match, then the headers matched on.
    fn gold_in_eu(x_match: &str) -> FieldTable {
        let mut arguments = FieldTable::default();
        arguments.insert("x-match".into(), AMQPValue::LongString(x_match.into()));
        arguments.insert("region".into(), AMQPValue::LongString("eu".into()));
        arguments.insert("tier".into(), AMQPValue::LongString("gold".into()));
        arguments
    }

    /// Gold shipments in the EU: both headers have to match.
    #[subscriber(RabbitQueue::new("couriers.express")
        .bind_with(RabbitExchange::headers("shipments"), "", gold_in_eu("all")))]
    async fn book_express(shipment: &Shipment) -> HandlerOutcome {
        tracing::info!(shipment.order_id, "express courier booked");
        HandlerOutcome::ack()
    }

    /// Shipments that are gold or in the EU: one header is enough.
    #[subscriber(RabbitQueue::new("insurance")
        .bind_with(RabbitExchange::headers("shipments"), "", gold_in_eu("any")))]
    async fn insure(shipment: &Shipment) -> HandlerOutcome {
        tracing::info!(shipment.order_id, "shipment insured");
        HandlerOutcome::ack()
    }

    headers 交换机按消息头而不是路由键来路由。 bind_with 为绑定指定参数：要匹配的消息头，以及 x-match，它规定其中多少个必须匹配。 取 all 时，消息必须匹配全部消息头；取 any 时，匹配一个就够了。 ship_order 用 with_headers 为每次发货设置 region 和 tier。 欧盟的 gold 级发货到达两个队列，欧盟的 silver 级发货只到达保险队列，美国的 silver 级发货哪个队列也不到达。

    普通的 bind 用于按路由键路由的交换机。 在 headers 交换机上，它建立的绑定没有要匹配的消息头，而对空集合取 all 对每条消息都成立。 FieldTable 和 AMQPValue 来自 lapin，由 prelude 重新导出。

    src/main.rs
    #[ruststream::app]
    fn app() -> impl App {
        let broker = LapinBroker::new("amqp://localhost:5672").declare_topology(true);
        RustStream::new(AppInfo::new("shop", "0.1.0")).with_broker(broker, |b| {
            b.include(place_order)
                .out(DefaultSlot, Publish::default().exchange("events"))
                .build();
            b.include(notify_customer);
            b.include(reserve_stock);
            b.include(audit);

            b.include(change_price)
                .out_reply(Publish::default().exchange("prices"));
            b.include(refresh_storefront);
            b.include(reindex);

            b.include(ship_order)
                .out(DefaultSlot, Publish::default().exchange("shipments"))
                .build();
            b.include(book_express);
            b.include(insure);
        })
    }
    src/main.rs
    fn app() -> impl App {
        let broker = LapinBroker::new("amqp://localhost:5672").declare_topology(true);
        let events = RabbitExchange::topic("events");
        let prices = RabbitExchange::fanout("prices");
        let shipments = RabbitExchange::headers("shipments");
        RustStream::new(AppInfo::new("shop", "0.1.0")).with_broker(broker, |b| {
            b.include(subscriber("orders", PlaceOrder).build())
                .out(DefaultSlot, Publish::default().exchange("events"))
                .build();
            b.include(
                subscriber(
                    RabbitQueue::new("notifications.orders").bind(events.clone(), "order.placed.*"),
                    NotifyCustomer,
                )
                .build(),
            );
            b.include(
                subscriber(
                    RabbitQueue::new("warehouse.eu").bind(events.clone(), "*.*.eu"),
                    ReserveStock,
                )
                .build(),
            );
            b.include(subscriber(RabbitQueue::new("audit").bind(events, "#"), Audit).build());

            b.include(subscriber("catalog.prices", ChangePrice).reply().build())
                .out_reply(Publish::default().exchange("prices"));
            b.include(
                subscriber(
                    RabbitQueue::new("storefront.prices").bind(prices.clone(), ""),
                    RefreshStorefront,
                )
                .build(),
            );
            b.include(subscriber(RabbitQueue::new("search.prices").bind(prices, ""), Reindex).build());

            b.include(subscriber("orders.paid", ShipOrder).build())
                .out(DefaultSlot, Publish::default().exchange("shipments"))
                .build();
            b.include(
                subscriber(
                    RabbitQueue::new("couriers.express").bind_with(
                        shipments.clone(),
                        "",
                        gold_in_eu("all"),
                    ),
                    BookExpress,
                )
                .build(),
            );
            b.include(
                subscriber(
                    RabbitQueue::new("insurance").bind_with(shipments, "", gold_in_eu("any")),
                    Insure,
                )
                .build(),
            );
        })
    }

    fn main() -> ExitCode {
        run_main(app)
    }

    交换机只在挂载点的策略上写一次：Publish::default().exchange("events")。 处理器的函数体只写消息及其路由键，所以只要挂载点换一个交换机，同一个处理器就发布到那里。 回复在 .out_reply(..) 处接收同样的策略。

    RabbitMQ 拒绝发布到不存在的交换机，并关闭发布所用的信道。 这里的订阅在启动时、在任何处理器发布之前声明 events、prices 和 shipments。 如果服务发布到一个它并不从中读取的交换机，就要依靠运维或另一个服务来声明这个交换机。

    订阅的每个绑定也出现在服务的 AsyncAPI 文档中，位于其通道的 x-ruststream-amqp 扩展里。

    一致性哈希​

    plugin-consistent-hash feature 加入 RabbitExchange::consistent_hash，即 RabbitMQ 一致性哈希插件提供的交换机类型。 它按路由键的哈希把一个消息流分散到多个队列，每个队列以自己的权重作为路由键进行绑定。 路由键相同的消息总是到达同一个队列。 插件必须在服务器上启用，路由也只在服务器上发生，所以它的测试针对真实的 RabbitMQ 运行。

    测试​

    示例文件中的测试发布一个订单、一次价格变动和三个已支付订单，并检查每条消息到达了哪些队列。 进程内 RabbitMQ 按描述符声明的同一组绑定，通过默认、direct、topic、fanout 和 headers 交换机进行路由。 测试 RabbitMQ 服务讲解了测试套件。
