# Обменники и маршрутизация

Это руководство направляет сообщения через обменники RabbitMQ: по ключу маршрутизации, во все привязанные очереди и по заголовкам.

Издатель никогда не пишет в очередь.
Он публикует сообщение в обменник с ключом маршрутизации, а обменник копирует сообщение в каждую очередь, привязка которой подходит.
В RustStream привязки очереди задаются в её [дескрипторе](../components/subscriptions/rabbit-queue.md), а обменник, в который уходит сообщение, - в [политике публикации](../components/publishing/exchange.md).
Ключ маршрутизации - это имя сообщения: `#[outgoing(name = "..")]` его типа или имя, которое задаёт публикация.

Пример - магазин, который сообщает о заказах через обменник типа `topic`, об изменениях цен - через обменник типа `fanout`, а об отгрузках - через обменник типа `headers`.
Брокер объявляет обменники, очереди и привязки, поэтому пример работает на пустом RabbitMQ ([Топология](topology.md)).

## Обменник по умолчанию

Все сервисы до сих пор публиковали в обменник по умолчанию.
Это обменник типа `direct`, к которому каждая очередь привязана под собственным именем.
Поэтому сообщение с ключом маршрутизации `orders` попадает в очередь `orders`, и сервис читает его через `#[subscriber("orders")]` без всякой привязки.
Привязку к обменнику по умолчанию отвергают и сервер, и RabbitMQ внутри процесса.

Собственный [обменник типа `direct`](../components/exchanges/index.md) маршрутизирует так же: привязка называет один ключ маршрутизации, и сообщение попадает в очереди, привязанные ровно под его ключом.

`place_order` публикует каждый заказ как `OrderPlaced` с ключом маршрутизации `order.placed.<region>`.
Тип не объявляет имени, поэтому имя задаёт публикация через `.to(&key)`.
[Обменник типа `topic`](../components/exchanges/topic.md) сравнивает ключ с шаблоном каждой привязки по словам, разделённым точками.
`*` заменяет ровно одно слово, а `#` - любое число слов, в том числе ни одного.

Поэтому `order.placed.*` принимает заказы всех регионов, `*.*.eu` - только заказы из ЕС, а `#` - все сообщения обменника.
Заказ из США попадает в уведомления и в аудит, а европейский склад его не видит.
Обработчик читает ключ, с которым пришло сообщение, через [`Ctx<RoutingKey>`](../components/context/index.md).

[Обменник типа `fanout`](../components/exchanges/fanout.md) копирует каждое сообщение во все привязанные к нему очереди и не смотрит на ключ маршрутизации.
`change_price` отвечает сообщением `PriceChanged`, и витрина и поисковый индекс получают каждый свою копию.
Привязки называют пустой ключ, потому что обменник ключ не читает.
Новый читатель изменений цен - это ещё одна очередь, привязанная к `prices`; издатель при этом не меняется.

Обменник типа `headers` маршрутизирует по заголовкам сообщения, а не по ключу.
[`bind_with`](../components/exchanges/bind-with.md) задаёт аргументы привязки: заголовки для сравнения и `x-match`, который говорит, сколько из них должно совпасть.
При `all` сообщению нужны все заголовки, при `any` достаточно одного.
`ship_order` ставит каждой отгрузке заголовки `region` и `tier` через `with_headers`.
Золотая отгрузка в ЕС попадает в обе очереди, серебряная в ЕС - только в страхование, а серебряная в США - никуда.

Простой `bind` нужен для обменников, которые маршрутизируют по ключу.
На обменнике типа `headers` он создаёт привязку без заголовков для сравнения, а условие `all` по пустому набору заголовков истинно для любого сообщения.
[`FieldTable`](api:ruststream_lapin::FieldTable) и [`AMQPValue`](api:ruststream_lapin::AMQPValue) взяты из lapin и реэкспортируются в прелюдии.

Обменник называется один раз, в политике в точке монтирования: [`Publish::default().exchange("events")`](api:ruststream_lapin::LapinPublish::exchange).
Тело обработчика называет только сообщение и его ключ, поэтому тот же обработчик публикует в другой обменник, если так указано в точке монтирования.
Для ответа та же политика указывается в `.out_reply(..)`.

RabbitMQ отвергает публикацию в несуществующий обменник и закрывает канал, через который она шла.
Здесь подписки объявляют `events`, `prices` и `shipments` при запуске, до того как какой-либо обработчик начнёт публиковать.
Если сервис публикует в обменник, из которого не читает, объявить этот обменник должны эксплуатация или другой сервис.

Каждая привязка подписки появляется и в документе AsyncAPI сервиса, в расширении [`x-ruststream-amqp`](../components/asyncapi/extension.md) её канала.

## Согласованное хеширование

Фича `plugin-consistent-hash` добавляет [`RabbitExchange::consistent_hash`](../components/exchanges/consistent-hash.md) - тип обменника из плагина согласованного хеширования RabbitMQ.
Он распределяет один поток сообщений по нескольким очередям по хешу ключа маршрутизации, а каждая очередь привязывается со своим весом в качестве ключа маршрутизации.
Сообщения с одинаковым ключом всегда попадают в одну и ту же очередь.
Плагин должен быть включён на сервере, и маршрутизация выполняется только там, поэтому его тесты работают на настоящем RabbitMQ.

## Тестирование

Тесты в файле примера публикуют заказ, изменение цены и три оплаченных заказа и проверяют, в какие очереди попало каждое сообщение.
RabbitMQ внутри процесса маршрутизирует через обменники по умолчанию, `direct`, `topic`, `fanout` и `headers` по тем же привязкам, которые объявляют дескрипторы.
Обвязку разбирает руководство [Тестирование сервиса на RabbitMQ](testing.md).
