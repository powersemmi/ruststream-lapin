# Модель

RabbitMQ направляет сообщение через обменник в очереди по привязкам, а потребитель читает одну
очередь через канал соединения.

<Diagram name="model" words={words} />

Производитель никогда не пишет в очередь. Он публикует сообщение в обменник и задаёт ему ключ
маршрутизации. Обменник сверяет сообщение со своими привязками, и каждая очередь с подходящей
привязкой получает копию. Сообщение, которому не подходит ни одна привязка, не попадает ни в одну
очередь.

Очередь - это хранилище, которое опустошает потребитель. Сообщение покидает очередь, когда
потребитель его подтверждает. До этого сервер хранит его, а доставка, которую потребитель вернул
или так и не подтвердил, возвращается в очередь.

На каждом сервере есть обменник по умолчанию с пустым именем. Каждая очередь привязана к нему под
своим именем, поэтому публикация в обменник по умолчанию с ключом маршрутизации `orders` попадает
в очередь `orders`. Так сервис без собственной топологии всё равно публикует в очередь.

Обменники, очереди и привязки находятся в виртуальном хосте, который указан в URI соединения.
Клиент открывает одно соединение TCP и выполняет работу в каналах внутри него. Канал - лёгкий
сеанс с собственным состоянием: окном предвыборки, режимом подтверждений, транзакцией. Ошибка в
канале закрывает этот канал, а соединение остаётся открытым.

Модель - это AMQP 0.9.1 в реализации RabbitMQ
([понятия AMQP](https://www.rabbitmq.com/tutorials/amqp-concepts),
[каналы](https://www.rabbitmq.com/docs/channels),
[обменник по умолчанию](https://www.rabbitmq.com/docs/exchanges#default-exchange)). Как
маршрутизирует обменник каждого типа, показывает страница [Типы обменников](routing.md), как
очередь передаёт сообщения потребителям - страница [Потребители и предвыборка](consumers.md), а
чем различаются два типа очередей - страница [Классические и кворумные очереди](queues.md).
