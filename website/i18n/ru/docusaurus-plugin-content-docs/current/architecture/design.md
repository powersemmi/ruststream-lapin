# Устройство

Где стоит `ruststream-lapin`: между рантаймом RustStream и клиентом lapin, одно соединение, свой
канал у каждой подписки.

<Diagram name="design" words={words} />

Крейт реализует трейты брокера из ядра поверх [lapin](https://docs.rs/lapin/4.12.0/lapin/),
клиента AMQP 0.9.1 на чистом Rust. Рантайм над ним один для всех брокеров. Всё, что относится к
RabbitMQ, находится в этом крейте: [дескрипторы очередей](rabbitmq/queues.md), кадры, которые
отправляет подтверждение, адрес копии для переобработки и три
[режима публикации](rabbitmq/publishing.md).

Один брокер открывает одно соединение. Каждая подписка читает очередь через собственный канал,
поэтому её окно предвыборки и её ошибки касаются только её. Издатели без подтверждения доставки
делят один канал. Издатель с подтверждениями, транзакционный издатель и запрашивающая сторона
открывают собственный канал при первом использовании, потому что режим подтверждений, транзакция и
потребитель ответов - это состояние канала.

Ошибка канала закрывает один канал, а соединение остаётся открытым. Канал издателя открывается
заново при следующем использовании, поэтому одна публикация в несуществующий обменник не мешает
сервису публиковать дальше.

[`LapinBroker`](api:ruststream_lapin::LapinBroker) по умолчанию ничего не объявляет. Тогда
дескриптор описывает топологию, которую ожидает сервис, а подписка на несуществующую очередь
возвращает ошибку.
[`declare_topology(true)`](api:ruststream_lapin::LapinBroker::declare_topology) включает
объявление: каждая подписка объявляет свои обменники, свою очередь и свои привязки, именно в
этом порядке.

Запрашивающая сторона читает ответы в задаче на том рантайме, где брокер подключился, из какого бы
потока ни пришёл первый запрос.

Как части запускаются и останавливаются, показывает страница [Жизненный цикл](lifecycle.md), а
путь одной доставки - страница [Путь](path.md).
