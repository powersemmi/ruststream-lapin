# Жизненный цикл

[`LapinBroker::new`](api:ruststream_lapin::LapinBroker::new) записывает конфигурацию, connect
открывает соединение, запуск открывает канал и потребителя для каждой подписки, а завершение
работы закрывает соединение.

<Diagram name="lifecycle" words={words} />

`new` не выполняет ввода-вывода, поэтому билдер сервиса остаётся синхронным. Рантайм подключает
брокер при запуске приложения. Подключение открывает соединение AMQP по URI с именем
[`connection_name`](api:ruststream_lapin::LapinBroker::connection_name), которое показывает
интерфейс управления, и открывает общий канал публикации. Если сервер отказывает в соединении,
запуск прерывается.

Дескриптор каждой подписки разрешается один раз, по подключённому брокеру. Запуск прерывается на
первой подписке, которая не может открыться:

1. Очередь проверяет объявление переобработки. `max_attempts` и `dead_letter` становятся
   аргументами самой очереди. Кворумной очереди нужны оба и брокер, который её объявляет;
   классическая очередь принимает только `dead_letter`; очередь, заданная одним именем, не
   принимает ни одного.
2. Подписка открывает свой канал.
3. При [`declare_topology(true)`](api:ruststream_lapin::LapinBroker::declare_topology) она
   объявляет свои обменники, свою очередь, свои привязки и цель задержки. Объявление, которое
   расходится с тем, что хранит сервер, отклоняется с `PRECONDITION_FAILED`, а ошибка называет
   очередь и отправленные аргументы.
4. Подписка отправляет `basic.qos` с окном предвыборки, если оно задано.
5. Для [`delay`](api:ruststream_lapin::RabbitQueue::delay), который брокер не объявляет,
   проверяется, что цель существует: очередь ожидания или отложенный обменник. Если цели нет,
   запуск прерывается с ошибкой, которая называет и подписку, и цель.
6. Подписка запускает потребителя командой `basic.consume`. Несуществующая очередь прерывает
   запуск на этом шаге.

Проверка задержки нужна, потому что отложенная копия публикуется без ожидания ответа, а оригинал
подтверждается после неё. Сервер отбрасывает копию, отправленную в несуществующую очередь
ожидания, и без проверки сообщение терялось бы без ошибки. Проверка стоит одного обмена с сервером
при запуске и ничего не стоит на каждом сообщении.

Сервис, который только читает, других каналов не открывает. Первая публикация через
[политику с подтверждениями или транзакцией](rabbitmq/publishing.md) и первый запрос открывают
нужный каждому из них канал.

Завершение работы сначала помечает соединение закрытым, чтобы издатель, который ещё держит его, не
успел отправить сообщение, а затем закрывает соединение штатным закрытием AMQP. Сервер возвращает в
очередь всё, что подписки держали неподтверждённым.
[`ClosedLapinBroker::handshake`](api:ruststream_lapin::ClosedLapinBroker::handshake) сообщает,
состоялось ли штатное закрытие. Издатель или запрашивающая сторона, пережившие соединение, после
завершения работы отвечают [`AmqpError::Closed`](api:ruststream_lapin::AmqpError::Closed), а
подтверждение доставки после завершения работы возвращает ошибку вместо подтверждения, которого не
было.

## Восстановление соединения

Восстановление по умолчанию выключено. С `LapinBroker::auto_recover(true)` подключённый брокер может быть подключён или переподключаться без изменения своего типа Rust.
`is_connected()` сообщает состояние AMQP-соединения; при результате true восстановление каналов и топологии ещё может продолжаться.
Lapin восстанавливает существующие каналы и их топологию, не пересоздавая приложение. Хуки запуска повторно не выполняются.
`recovery_retries(n)` ограничивает повторные попытки при запуске и дальнейшем восстановлении (по умолчанию 16). При исчерпании попыток поток потребителя заканчивается ошибкой чтения.
Завершение работы во время восстановления сразу закрывает доступ через существующие объекты и пробуждает ожидающих потребителей; сокет, подключённый позже, закрывается в фоне.
